# Quarrix: notes for Claude

PySide6 application (public repository) that extracts PDFs while keeping their
hierarchy, into the output folder chosen by the user (`output_dir`, no default).
`quarrix dist` builds the distributable pack; `--publish-dir` copies it (and
nothing else) elsewhere. Do not put project-specific paths or names in the code.

**English first**: README, documentation, code, comments and the user interface
are written in English. Screenshots and examples use fictional documents and
names only; never real documents, personal paths or personal data.

- `quarrix/engines/`: Docling (recommended) and PyMuPDF (fallback) engines. Both
  produce an `ExtractedDocument` (`quarrix/model.py`); no output logic in engines.
- `quarrix/writer.py`: writes `document.md`, `document.json`, `meta.json`, CSV and
  PNG. `meta.json` must never be overwritten (data entered by hand). Keep every
  output file well under GitHub's 100 MB limit (compact JSON, no raw Docling
  export by default; see "File size" in `docs/FORMAT.md`).
- `quarrix/dist.py`: distributable pack. Any change must keep the rule
  "`full` only if the licence allows it, otherwise `derived`".
- `quarrix/doctypes.py` + `default_types.toml`: classification (category,
  author/distributor, type, subjects). Each type carries its Docling settings,
  translated by `build_pipeline_options`; the `Extractor` keeps one engine per setting.
- Format documented in `docs/FORMAT.md`; bump `SCHEMA_VERSION` on incompatible changes.
- Tests: `pytest` (the sample PDF is generated by `tests/make_sample.py`).
- Never commit PDFs or extracted data to this repository.
